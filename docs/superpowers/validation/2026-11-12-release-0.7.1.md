# 留白 0.7.1 发布验证

日期：2026-11-12。正式构建来源为 `df69788`（附注标签 `v0.7.1`）。

## 发布前

- 工作区的 172 个已跟踪改动与 15 个新文件分成三个提交入库：应用与前端、检查脚本与 CI、文档与设计记录。版本号改为 0.7.1（`mygo.json`、`package.json`），`CHANGELOG.md` 顶部的「未发布」定为 `## 0.7.1`，新增 `docs/releases/0.7.1.md`。
- `npm run check` 通过；`node scripts/build.mjs` 重建的 `web/` 与提交内容逐字节一致，重复构建结果相同。
- `go test ./...` 通过（31.282s）。
- GitHub CI 首次运行：Windows 通过；macOS 在 `check-extras.ts` 的脚注装饰预算上失败（27.38ms，预算 15ms/不可缩放），重跑通过。该预算是共享 runner 上唯一没有缩放的字面预算，已改为读取 `PERF_BUDGET_SCALE`，UI 检查步骤设为 4（本机同一用例 10.8–11.5ms）。此修改在标签之后单独提交，不改变正式产物。

## 正式产物

- `go tool mygo build -platform darwin/universal,windows/amd64,windows/arm64 -o build/release-0.7.1 .` 成功；更新签名私钥只传入构建子进程的环境。
- macOS App 与 DMG 均通过严格 codesign 校验、Gatekeeper 评估（`accepted`，`source=Notarized Developer ID`）、stapler 票据校验；DMG 通过 `hdiutil verify`。
- Universal App 的 arm64 薄片，以及 Windows x64/ARM64 程序，均记录 `vcs.revision=df697889ba3886b682a40fb2d673176c7807f578`、`vcs.modified=false`；Windows 程序为 PE32+ GUI，安装包为 Nullsoft Installer。
- App 内所有 Git 跟踪的 `web/` 文件与仓库逐字节一致；只差 Finder 的 `.DS_Store`，它未进入应用资源。
- 3 个完整更新包与 9 个增量包（各平台从 0.7.0、0.6.7、0.6.6 升级）的大小与三份更新源一致，12 份签名均用 `mygo.json` 里的 Ed25519 公钥验证通过。
- `SHA256SUMS` 沿用 0.6.7 与 0.7.0 的做法：按同样的文件名另行计算，比构建生成的多三个更新源，共 20 行；逐行复核通过。
- 发布资源共 21 个：3 个安装包、3 个完整更新包、9 个增量包、3 个更新源、2 个安装脚本、`SHA256SUMS`。上传后通过 GitHub API 核对全部 21 个资源的名称、状态、大小和 SHA256 digest，与本地产物一致。

## 官网

网站仓库 `echovic-apps` 提交 `4d22134` 已推送并部署：`products/liubai.json` 的 `fallbackTag` 与三个兜底安装包改为 0.7.1，截图和文案没有改（本版没有需要换图的界面变化）。随后用 0.7.1 的构建重拍了主题面板的两张截图（`31c796a`）：浅色版与旧图逐像素相同，没有替换；深色版只有对话框圆角处的 532 个像素因遮罩压暗而变深，整张图几乎看不出差别。这说明这两张截图的构图拍不到本版的主题修复（深色阴影、Solarized Dark 的次要文字色、悬停与按下状态），要展示它们需要换一种构图。页面里写死的版本号与三个安装包直链已由构建写成 0.7.1。

构建时只有留白的 5 个文件与线上不同：中英文首页、中英文更新日志和 sitemap。其余产品的中英文首页、更新日志、sitemap 和图标资源都与线上逐字节一致；其中两个产品的更新日志和五个产品的 sitemap 先在 `public/` 里恢复成线上版本再部署，因为本地 checkout 的 CHANGELOG 与线上部署时读到的来源不一致。部署后 20 个非留白页面重新下载，与部署前逐字节一致。

部署后匿名下载留白四个页面，与本地构建逐字节一致，版本号显示 0.7.1；三个安装包直链返回 200。没有用真实浏览器打开页面确认，运行时从 GitHub API 取版本号这条路径未单独验证。
