# 标签筛选设计

**日期**：2026-10-28  
**状态**：已完成实施及 TF-1 至 TF-9 验收；用户已授权「好的，开始做标签筛选功能」。实测与验证边界见实施计划。  
**基础**：已有全文搜索、Markdown front matter 标签、最近文稿和安全搜索导航。  
**实施计划**：[标签筛选](../plans/2026-10-28-tag-filter.md)。

## 功能契约

侧栏增加一个紧凑的原生标签选择器，默认“全部标签”。选择标签，或点击文稿旁的标签，显示带有该标签的已登记文稿。关键词与标签取交集；标签匹配来自 front matter 的 `tags` 属性，不能把正文里出现的 `#工作` 当作标签。

首版单选一个标签。标签筛选覆盖 `Workspace.docs` 中所有工作副本，包含草稿和已打开文件，移除、废纸篓、隔离目录和未登记文件不参与。筛选读取已接受的内容，不读盘、不保存、不修改当前文稿和通知。保存、打开、新建、移除、重命名、随手记和语言切换之后刷新。

清空关键词保留所选标签；清除标签保留关键词；两者为空恢复原来的最近文稿列表及移除确认。搜索框 Esc 按这个顺序清除关键词、清除标签、关闭侧栏。筛选结果保留当前编辑、分栏或阅读模式；点击正文片段和“在源码中查看”复用已有导航。

标签没有独立数据库，筛选选择不写入 `Appearance` 或文稿存储；关闭重开侧栏保留本页选择，重新启动回到“全部标签”。

## 标签语义

复用 `summaryOf`、`captureTagValues` 和 `normalizeTags` 的现有读取规则：支持字符串和字符串列表、去除周围空白和一个显示前缀、按原规则去重，单标签最多 80 个 Unicode 字符，每文稿最多 32 个。缺失、非法 YAML 或不支持的标签属性按无标签处理，文稿仍能正常搜索。

筛选请求接收读取器返回的规范标签名，采用大小写敏感的完整匹配；不再去掉 `#`，避免对本来含有 `#` 的规范标签二次转换。`Work` 和 `work` 是不同标签。标题与正文的关键词继续使用原有字面、大小写不敏感规则，UTF-16 坐标保持不变。

标签目录按名称稳定排序，计数为携带标签的登记文稿数，每篇对一个标签只计一次。目录计数独立于当前关键词和所选标签，用户输入关键词时其他标签仍可选择。已选标签最后一篇文稿被移除或改掉标签时，保留选择并显示 0 篇，不自动扩大结果范围。

## 实现选择

采用 Go 工作副本快照筛选：解析标签、计算目录，在符合标签的快照上复用全文匹配和排序。前端统一调度关键词与标签请求，使用现有安全导航。

只过滤前端结果会受全文搜索 100 篇展示上限影响，无法可靠得到交集总数；持久标签索引则需要增加维护协议。本次复用现有快照和解析器。

## API 与类型

保留 `Search(query)` 及其返回类型。新增原生和浏览器共用的 `FilterDocuments`：

```go
type DocumentFilterRequest struct {
    Query string `json:"query"`
    Tag   string `json:"tag"`
}

type TagSummary struct {
    Name  string `json:"name"`
    Count int    `json:"count"`
}

type DocumentFilterItem struct {
    Document SearchItem `json:"document"`
    Tags     []string   `json:"tags"`
    Excerpt  string     `json:"excerpt"`
}

type DocumentFilterResponse struct {
    Items     []DocumentFilterItem `json:"items"`
    Total     int                  `json:"total"`
    Truncated bool                 `json:"truncated"`
    Tags      []TagSummary         `json:"tags"`
    Recent    []Summary            `json:"recent"`
}
```

`Workspace.FilterDocuments(request, locale)` 在锁内只取不可变快照，锁外解析和查询。复用全文搜索的查询校验。请求标签检查 UTF-8、80 字符和控制字符，周围空白可移除，其余内容保留。

有关键词或标签时返回最多 100 篇结果、每篇最多 3 个正文命中，`total` 和 `truncated` 对应完整交集。关键词为空时按更新时间倒序、ID 稳定排序，正文命中为空数组；摘要仅为这类结果构造，复制为最多 90 字符的小字符串。关键词不为空时使用原来的标题优先和正文匹配排序。

两者为空时 `items=[]`、`total=0`、`truncated=false`，返回全局标签目录及与原最近列表相同范围的 `recent` 元数据；前端恢复原列表。已有 `WorkspaceState.recent` 实际包含全部登记文稿，本次不暗中增加最近列表限额。其他请求的 `recent=[]`，避免每次关键词查询额外传输整份最近列表。

所有数组始终是数组，不返回 `null`，不返回完整正文。原生使用当前应用语言，浏览器使用请求语言，不通过筛选改变全局语言。生成绑定和语言目录，不手工改生成产物。

## 侧栏与模块

选择器置于搜索框下方，使用现有选择控件、11 套主题角色和系统字体。标签旁显示文稿数量，选择器有明确的标签筛选名称。无标签时仍显示“全部标签”，不挤占正文或增加新的侧栏页签。

文稿标签为独立小按钮，不嵌套在打开文稿的按钮内。每篇显示最多三个；已选标签优先包含在可见标签中，其余以数量提示，完整标签可从选择器访问。重复点击所选标签清除选择，其他标签替换当前选择。按钮使用墨色和细线表达状态，键盘可见焦点、`aria-pressed` 和中英文说明齐全。

`src/tag-filter.ts` 只承担标签选项和标签按钮的 DOM 构造；`src/search.ts` 保持查询状态、选择、请求和焦点管理；`src/app.ts` 负责已有最近列表与导航的连接。不会抽出无关编辑器或设置逻辑。

## 异步与安全

统一查询任务携带 `query` 和 `tag`，180 ms 防抖，一个请求在途，后面只保留最新任务。初次打开、空筛选和刷新最近列表也通过同一队列读取标签元数据；空筛选立即展示已有最近列表，待新元数据到达再更新。

输入、标签变化、语言变化、内容变动、关闭和组合输入立即失效旧任务，旧成功、旧错误和旧标签目录都不能覆盖当前状态。内容待保存时暂停请求和旧筛选结果的打开，保存失败保留文字和一致性提示，位置保存不刷新。

标签只作文本展示，使用文本节点和原生选项，不拼接 HTML。更新结果保留按钮和选择器焦点，用户移到编辑器后不抢回。只筛标签的文稿按钮同样使用搜索结果的 ID/revision 和保存保护；没有命中范围时只打开并聚焦内容，不猜测位置。

## 验收

- **TF-1 范围**：标签目录和筛选覆盖全部登记工作副本，超过 30 篇和 100 篇的场景不漏文稿，移除和未登记文件不在目录或结果中。
- **TF-2 交集与限制**：标签单独、关键词单独、两者交集均正确；正文尾部、中文、emoji、字面符号继续命中；100/3 上限与完整总数一致。
- **TF-3 标签读取**：字符串、列表、去重、大小写、含 `#` 的规范名和非法元数据符合上述语义；目录全局计数正确稳定。
- **TF-4 只读**：筛选前后内容、当前 ID、revision、更新时间、通知和文件字节不变，没有磁盘重载或 schema 变化。
- **TF-5 生命周期**：标签改变和空筛选使旧结果/错误/目录失效，一个在途；关闭、重开、语言和组合输入受保护；保存成功刷新，位置保存不刷新。
- **TF-6 导航**：标签筛选结果保留输入、撤销和三种视图；版本失效和移除结果不使用旧范围；标签按钮只筛选，不打开或修改文稿。
- **TF-7 状态**：清空词保留标签、清除标签保留词；最后一个标签文稿消失时保留零结果；空筛选恢复原移除确认。保存失败和重试不丢输入。
- **TF-8 界面**：中英文、十一主题、窄侧栏、Tab/方向键/Enter/Esc 和刷新焦点可用，没有嵌套交互控件或横向溢出。
- **TF-9 回归与性能**：Go/race/vet、TS、国际化、现有搜索、文内查找、随手记、侧栏和预览检查通过；保留 250 ms 后端与 600 ms 界面搜索预算。
